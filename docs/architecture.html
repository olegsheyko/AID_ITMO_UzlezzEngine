Коротко

Главный поток владеет окном, ImGui и всеми вызовами OpenGL. Воркеры enkiTS читают и декодируют сцены, меши и текстуры, а также вычисляют позы персонажей. Готовые CPU-данные возвращаются на главный поток через ограниченный по времени GPU upload pump. Tracy измеряет полный кадр, подсистемы, загрузку и работу воркеров.

01

Модули и направление зависимостей

Core и states

Application создаёт рендер, GUI, Job System и ресурсы. StateManager держит текущее состояние: Loading, Editor, Gameplay или отдельный AnimationBenchmark.

ECS

World хранит сущности и типизированные component storage. Поведение вынесено в физику, камеру, вращение, анимацию, основной и debug-рендер.

Resources

ResourceManager кэширует сцены, меши, текстуры и шейдеры. CPU-фаза загрузки отделена от GPU-финализации.

Render и editor

IRenderAdapter скрывает большую часть OpenGL. Редактор строит dockspace и показывает сцену из отдельного FBO внутри панели Viewport.

World хранит отдельный unordered_map<Entity, T> для каждого компонента. forEach перебирает первый storage и делает хеш-поиск остальных типов. Это просто и удобно для учебного проекта, но не даёт плотного линейного обхода.

Рендер пропускает сущности без готового шейдера. Загружаемый меш заменяется процедурным кубом, текстура — серой шахматкой. Для skinning передаются meshNodeTransform и uniform-массив boneMatrices[128].

04

Job System

Многопоточность реализована. Единственная очередь фоновой работы движка построена поверх enkiTS 1.12. Число воркеров по умолчанию выбирается планировщиком из аппаратной конфигурации.

submit

Обычные задачи с приоритетом High, Normal или Low. Ожидающий поток может помогать их выполнять.

submitBackground

Pinned-задачи для resource I/O. Они остаются на воркерах и не переносят декодирование на главный поток при ожидании анимации.

parallelFor

Синхронно делит диапазон на части не меньше minRange и ждёт завершения.

lifecycle

Хэндлы удерживают задачи до collectCompleted; shutdown ждёт даже задачи, поставленные из других задач.

Если scheduler не запущен, submit выполняет функцию сразу. Исключения внутри задачи логируются и не разрушают пул.

Код: src/jobs/JobSystem.h · src/jobs/JobSystem.cpp · tests/JobSystemTests.cpp

06

Скелетная анимация

Assimp импортирует иерархию, inverse bind matrices, TRS-ключи и веса вершин. Поддерживаются линейная интерполяция position/scale, кратчайший quaternion SLERP, максимум 128 костей на подмеш и четыре наибольших нормализованных веса на вершину.

Main · prepareСобирает готовые MeshData/Animator, обновляет время и подготавливает выходные буферы.
Workers · posesПакеты персонажей независимо вычисляют globals и палитры подмешей.
Main · waitЖдёт все пакеты; после барьера позы больше не меняются в этом update.
Main · renderПередаёт палитры uniform-массивом и выполняет GPU skinning в vertex shader.
512персонажей в приёмочном замере
0,636мс, parallel animation p50
3,709мс, sequential animation p50
5,670мс, parallel full-frame p50

Ограничения: нет blending, IK, retargeting, morph targets и извлечения root motion. OpenGL-вызовы не выполняются на воркерах.

Код: src/animation/ · src/ecs/AnimationSystem.cpp · src/editor/panels/RendererInfoPanel.cpp · assets/shaders/mesh_vertex.glsl.

07

Tracy 0.14.1

Клиент встроен в репозиторий и активен в Release/RelWithDebInfo при ENGINE_ENABLE_TRACY=ON. Используется режим TRACY_ON_DEMAND; profiler UI собирается отдельно и должен совпадать по версии протокола.

Кадр

Frame, Input, Present, ImGui draw, Simulation, Viewport и Scene render.

Ресурсы

Load mesh/texture/shader, Resource upload pump и график Loads pending.

Jobs

Имена Main/Job worker N, интервалы сна/ожидания enkiTS и график Jobs in flight.

Анимация

Prepare, dispatch, wait, poses, полный update и число Animated characters.

Windows-демо zones, locks, memory, messages и gpu используют D3D12 и не зависят от OpenGL-движка. Сохранённые трассы находятся в docs/lab1/acceptance/traces-final.

Код: CMakeLists.txt · external/tracy/README.engine.md · demos/tracy/ · Tracy-макросы в src/.

ЛР 2: Lua и префабы

Встроенный Lua 5.4.8 + sol2 3.3.1. Lua статически встроен в exe. ScriptSystem создаёт sol::state вместе с редактором и закрывает после освобождения всех ссылок sol2. Виртуальные lifecycle-методы ScriptBehaviour перенаправляются в защищённые Lua-вызовы через адаптер LuaBehaviour.

ScriptComponent хранит путь, класс и примитивные поля. Entity handle проверяет lifetime и поколение ID; World proxy инвалидируется при Stop. API предоставляет Transform, ввод, поиск по тегам, spawn JSON-префабов, отложенное destroy и управление скоростью анимации.

Окно Gameplay: Open Arena, Reload Scripts только в Edit, статус и ошибки Lua; HUD поверх Game. Inspector сохраняет поля в JSON. Play/Stop сохраняет и восстанавливает сцену. Preview Enemy предназначен для настройки префаба и не участвует в Play.

Вся механика — core.lua, enemy.lua, waves.lua: Space запускает волну, F — защитный импульс. Анимированные враги идут к ядру и наносят урон. Ошибки показываются с traceback. Lua-скрипты доверенные; лимиты времени/памяти не реализованы, библиотеки package/io/os/debug не открываются.

Код: src/scripting/ · src/prefabs/ · src/editor/panels/GameplayPanel.cpp · assets/scripts/ · assets/prefabs/. Инструкция ЛР 2.

09

Текущие ограничения и точки роста

ECS layout

Хеш-таблицы и дополнительные lookup вместо dense storage/sparse set; порядок обхода нестабилен.

Render submission

Камера ищется для каждого меша, world matrix собирается рекурсивно, нет сортировки и batching.

Материалы

В данных есть normal/metallic/roughness/AO/height, но текущий render path использует только diffuse/base color.

GPU upload

Одна неделимая 2K-заливка может превысить временной бюджет; mipmap generation остаётся на главном потоке.

States

Переходы знает Application через dynamic_cast; Menu/Gameplay не входят в обычный маршрут.

Engine context

Logger, ResourceManager, HotReload, InputManager и JobSystem — глобальные singleton-сервисы.

Важно для сопровождения: ResourceManager предполагает main-thread API; нельзя обращаться к его кэшам из произвольной задачи. Воркеры владеют только своими CPU-данными до публикации шага финализации.
