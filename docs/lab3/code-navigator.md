# ЛР 3: куда смотреть в коде

Шпаргалка к вопросу преподавателя «покажите, как у вас сделано X» для варианта Д (culling + submission).
Подробные объяснения в [lab3-explained.pdf](lab3-explained.pdf), презентация в [lab3-defense.html](lab3-defense.html),
описание автора в [docs/culling/README.md](../culling/README.md).

## Как открыть быстро

- Cmd+P: имя файла (`RenderSystem.cpp`). Cmd+Shift+O: функция в открытом файле. Cmd+T: функция по всему проекту.
- Cmd+G: перейти на строку. Номера сверены 20 октября 2026 после коммита `54eb67e`; после правок кода они поплывут,
  надёжнее искать по имени функции.

Четыре файла, которые нужно знать наизусть: `src/ecs/Visibility.h`, `src/ecs/SceneVisibility.h`,
`src/ecs/RenderSystem.cpp`, `src/editor/CullingScene.cpp`.

## 2. «Покажите, как у вас...»

### Реестр и изменения

**...регистрируется объект.**
`SceneVisibility.h:88` в `synchronize`: новый объект получает handle,
известный обновляется по своему (`SceneVisibility.h:89`).
Сказать: регистрирует не игровой код, а синхронизация, когда видит новую помеченную сущность с мешем и шейдером.

**...подсистема узнаёт о сдвиге объекта.**
`World.h:134` `notifyComponentEdit`, его зовёт неконстантный `getComponent`
(`World.h:70` и ниже). Сказать: доступ на запись сам помечает сущность; читающий код берёт
const или `forEachRead` (`World.h:125`). Анимация помечает явно: `AnimationSystem.cpp:33`.

**...работает синхронизация.**
`SceneVisibility.h:22`. Сказать по шагам: забрать помеченных и ждущих ресурс; добавить детей
(`SceneVisibility.h:27`); снять с учёта объекты без меша, шейдера или скрытые; посчитать мировую
матрицу и bounds; `register` или `update`. Вызов каждый кадр: `EditorContext.cpp:246`.

**...удаляется объект.**
`World.cpp:46` в `World::destroyEntity`: снятие с учёта сразу, без ожидания кадра.
`World::clear` очищает реестр (`World.cpp:63`).

**...handle защищён от устаревания.**
`Visibility.h:58` и `Visibility.h:85`: номера только растут, даже `clear()` их не сбрасывает.
`update` по удалённому handle вернёт `false`.

### Отсев

**...проверяется видимость.**
`Visibility.h:26` `Frustum`: шесть плоскостей из матрицы `projection × view`, затем `Visibility.h:37`:
для каждой плоскости угол коробки, дальний по нормали; если он снаружи, объект невидим. Порог `-1e-4`: граница считается видимой.

**...коробка переводится в мир.**
`Visibility.h:16`: 8 углов через матрицу, новый min/max. Работает при повороте и отрицательном масштабе.

**...отсекаются анимированные персонажи.**
`SkinBounds.h:12` коробка для каждой кости (один раз), `SkinBounds.h:34`
каждый кадр коробки костей матрицами позы и объединение. Сказать: вершина после скиннинга это выпуклая комбинация, поэтому лежит
в объединении. Плохие веса: объект рисуется всегда.

**...отсев выключается.**
`RenderSystem::cullingEnabled` (`RenderSystem.h:22`), галочка в `RendererInfoPanel.cpp:135`.
`query(..., false)` возвращает все записи.

### Пакет и подача

**...строится видимый набор и пакет.**
`RenderSystem.cpp:33`: камера, синхронизация, `query`, запись пакета (сущность, матрица, программа, меш, текстура,
глубина), сортировка по id, затем по ключам.

**...сортировка и её ключи.**
`RenderSystem.cpp:52`: кортеж `(shader, mesh, texture, depth, entity)`; `depthSortingEnabled` убирает глубину.
Счётчик инверсий: `RenderSystem.cpp:60`.

**...подача и фильтр смены состояния.**
`RenderSystem.cpp:64` обход пакета; `RenderSystem.cpp:120` программа и
`RenderSystem.cpp:202` текстура переключаются только при изменении, счётчики `shaderChanges`, `textureChanges`.

**...замер двух фаз.**
`RenderSystem.cpp:21`: `prepareMs` и `submitMs`; в редакторе к prepare прибавляется синхронизация из update
(`EditorContext.cpp:1354`).

### Сцена, панель, замеры

**...создаётся сцена.** `CullingScene.cpp:7`; кубы `CullingScene.cpp:63`; перестановка
ячеек `CullingScene.cpp:75`.

**...кнопки Add / Delete / Move.** `RendererInfoPanel.cpp:147`; движение 100 объектов `EditorContext.cpp:185`.

**...живой счётчик «в сцене vs на GPU».** `SceneViewPanel.cpp:636` в оверлее Scene View;
`RendererInfoPanel.cpp:138` в Renderer Info.

**...стенд замеров.** `CullingBenchmark.cpp:87` маршрут камеры и анимация; `CullingBenchmark.cpp:149` CSV;
ключи запуска `LaunchOptions.cpp:15`; матрица режимов в `tools/run_culling_bench.py`.

## 4. Чего нет, и как об этом честно сказать

- **RenderDoc-захват «после»** (обязателен для GL-команд) в репозитории отсутствует. На macOS RenderDoc с OpenGL не работает, снять на Windows.
- **Допфичи варианта Д** не сделаны: многопоточная сборка видимого набора, instancing, отсев по расстоянию, occlusion.
- **Индекс линейный**, O(N): сетку или BVH можно поставить внутрь `Service` без смены интерфейса.
- **Один объект = один draw**: сокращаются переключения состояния, а не вызовы.
- **Ускорение кадра от сортировки не доказано**: эффект ключей виден в счётчиках.
- **На Mac проверка картинки падает** на одном пикселе при сортировке: равная глубина, порядок отрисовки решает «ничью».

## 5. Если попросят сделать прямо сейчас

- **Отсев по расстоянию:** в `Service::query` отбросить запись, если центр коробки дальше радиуса от позиции камеры (её передать вторым параметром).
- **Сортировка только по глубине:** в `prepare` поставить `a.depth` первым в `std::tie`; счётчик смен текстур сразу вырастет.
- **Вторая камера:** `world.visibility.query(матрица)` с любой матрицей, подсистема не меняется.
